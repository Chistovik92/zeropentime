# zeropentime — дорожная карта по версиям

Как устроено: [ARCHITECTURE.md](ARCHITECTURE.md). Технические решения и задачи по фазам: [PLAN.md](PLAN.md). Здесь — **что и в какой версии получает пользователь** и когда версия считается готовой.

**Релиз выходит на каждую версию третьего уровня (x.y.z).** Минорная версия (x.y) — это веха из нескольких патч-релизов. Каждый патч-релиз — законченный и проверенный шаг, который можно поставить и использовать. Правила — в конце документа.

Сроки — оценка для 1–2 разработчиков.

## Требует ручной проверки

Решение от 2026-09-26: релизы выходят без проверки на реальных машинах (в этой среде её не провести), а непроверенное копится здесь и в разделе «Как проверено» заметок к релизу.

- [ ] Windows ↔ Linux в одной LAN: ping, SMB, исключение из панели ≤ 5 с (с 0.1.0);
- [ ] то же через интернет с пробросом порта (с 0.1.0);
- [ ] профиль сети «Частная» включается сам (с 0.1.2).

## 0.2 — Связь отовсюду

### 0.2.0 — узел знает свой адрес
- STUN на relay-узлах, определение внешнего адреса и типа NAT;
- UPnP / NAT-PMP / PCP: автоматический проброс порта на роутере;
- панель: тип NAT и внешний адрес каждого участника.

### 0.2.1 — пробивка NAT
- обмен кандидатами и одновременная пробивка (disco), переход на лучший путь;
- тестовый стенд в CI со всеми типами NAT (full-cone, restricted, port-restricted, symmetric).

### 0.2.2 — relay
- `zpt relay` (встроен в контроллер, может работать отдельно), UDP-режим, пересылает только зашифрованные пакеты;
- `MemberCert` — сертификат участника для доступа к relay;
- автоматический переход relay → прямое соединение;
- панель: прямое соединение или через relay, RTT, список relay-серверов.

### 0.2.3 — VLESS + Reality
- транспорт до relay по TCP/443, когда UDP заблокирован или режется;
- автопереключение UDP ↔ VLESS; внутри остаётся сквозное шифрование AWG.

### 0.2.4 — настоящая «локалка»
- broadcast и multicast (LAN-игры, mDNS, SSDP) с ограничением частоты;
- настройка комнаты: broadcast вкл / выкл / только mDNS.

**Итог вехи:** любые пары типов NAT соединяются (симметричный ↔ симметричный — через relay); при заблокированном UDP связь идёт через VLESS; LAN-игра с поиском по broadcast работает между Windows и Linux через интернет.

## 0.3 — Интернет через комнату

### 0.3.0 — доступ к сети за узлом (subnet router)
- узел объявляет свою сеть (например, `192.168.1.0/24`), админ одобряет в панели;
- участники видят устройства этой сети; конфликты адресов обнаруживаются.

### 0.3.1 — exit-узел на Linux
- объявление exit → одобрение → выбор на клиенте (CLI и панель);
- клиент на Linux: весь трафик через exit (policy routing).

### 0.3.2 — exit на клиенте Windows
- маршруты через интерфейс комнаты с исключениями для relay и пиров;
- DNS через exit, защита от утечек DNS и IPv6.

### 0.3.3 — kill switch
- блокировка интернета при потере exit (WFP / nftables);
- опция «оставить доступ к своей LAN».

### 0.3.4 — exit-узел на Windows и лимиты
- userspace NAT на gVisor;
- ограничение скорости на exit (на клиента и общее).

**Итог вехи:** `curl ifconfig.me` показывает IP exit-узла; тест на утечку DNS чистый; при отключении exit интернет блокируется и восстанавливается ≤ 10 с; из комнаты открывается веб-интерфейс домашнего роутера.

## Правила версий и релизов

- **Каждая версия x.y.z — отдельный релиз:** git-тег `vX.Y.Z`, бинарники через goreleaser, контрольные суммы, запись в [CHANGELOG.md](../CHANGELOG.md), заметки к выпуску на русском.
- **Третья цифра (z)** — очередной шаг вехи: небольшая функция и/или исправления. Исправление найденной ошибки выходит в ближайшем следующем z-релизе; если ошибка серьёзная (безопасность, потеря связи), срочный z-релиз выходит сразу, а плановые номера сдвигаются. Номера в этом документе — порядок шагов, а не обещание точного номера.
- **Вторая цифра (y)** — веха. До 1.0 новая веха может ломать совместимость — только с описанием миграции в заметках к релизу. После 1.0 ломающие изменения — только в новой мажорной версии.
- **Совместимость узла и контроллера.** Внутри одной вехи (любые z) — полная. С 0.2 контроллер поддерживает узлы текущей и предыдущей вехи, чтобы узлы можно было обновлять постепенно. Версия протокола — в пути API (`/api/v1/...`).
- **Готовность релиза.** Релиз выходит, только когда: CI зелёный на всех платформах; сквозные тесты проходят; пункты релиза проверены (автотестом или на ручном стенде — что именно, пишется в заметках). Невыполненный пункт переносится в следующий z-релиз, а не выпускается «как есть».
- **Предварительные сборки** между релизами — с суффиксом `-dev` (например `0.1.1-dev`), не публикуются как релизы.
